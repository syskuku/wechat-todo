## 🚨 首次使用引导（完成配置后本块将被删除，以后运行不再出现）

### ① 最重要：先建专用工作文件夹（务必先做）

请**在电脑上新建一个文件夹**（任意位置均可，例如 `D:\我的消息代办\`、`文档\消息工作区\`），作为本 skill 的**唯一工作区**——以后所有消息导出、待办文件（`今日待办.md`、`待办总表.md`、`日期纪要/`）、归档文件都保存在这个文件夹里。

- 让你的 agent **运行在这个文件夹中**（以它为当前工作目录/项目目录启动会话），skill 的所有读写都相对它进行；
- 若当前会话的工作目录还不是这个文件夹，**先停下来引导用户切换**，不要写到别处；
- 文件夹结构由第一次运行自动生成：

```text
消息工作区/
├── README.md          ← 断点时间戳、必盯会话清单、个人范围限定、优先级规则
├── 今日待办.md          ← 主文件：今天的勾选清单（滴答勾掉=已完成）
├── 待办总表.md          ← 全部待办倒叙排列（最新在顶）
├── 日期纪要/YYYY-MM-DD.md ← 每日消息背景
├── 原始消息/            ← 完整聊天记录导出（核对用）
└── （归档文件夹，按用户的资料分类自建）
```

### ② 本 skill 的用途与用法

- **触发**：说"更新待办 / 生成今天的待办 / 同步滴答 / 整理微信消息 / 跑一下待办"即可；
- **干四件事**：扫微信增量消息 → 写待办文件 → 去重提交滴答清单 → 归档新文件 → 汇报；
- **依赖 1（微信读取）**：wechat-cli（`~/.wechat-cli/wxcli.cmd`）与检索脚本 `search_all.py` **已由安装器随包装好**（后者位于 `skills/wechat-local/scripts/`）。首次运行先验一步：`wxcli sessions` 能返回会话列表即可用；若报密钥错误或出乱码，保持微信运行后跑 `~/.wechat-cli/wxcli.cmd init` 重建密钥（config.json 的 db_dir 会自动探测），结果告知用户；
- **依赖 2（滴答清单 MCP）**：安装时若带了 `--token` 已自动写入配置；未接入时**其他步骤照常做，滴答同步步骤跳过并在汇报中明确说明**。

### ③ 接入滴答清单 MCP（TickTick / 滴答清单）

**方式 A（推荐）· 安装器自动写入：**
1. 到滴答清单开发者平台生成**个人访问令牌**（personal access token；可搜索"滴答清单 MCP 官方文档"进入 developer.dida365.com 获取）；
2. 重跑一行安装命令带上令牌：`npx github:syskuku/wechat-todo --token <你的令牌>` —— 自动写入本机 AI 工具的 MCP 配置（ZCode → `~/.zcode/cli/config.json` 的 `mcp.servers`；Claude Code → `~/.claude.json` 的 `mcpServers`）。

**方式 B · 手动粘贴**（没有自动写入时用）：把 `<你的令牌>` 换成自己的，加入你所用工具的 MCP 配置（Claude Code 放在顶层 `mcpServers` 下）：

```json
{"mcp":{"servers":{"滴答清单":{"type":"http","url":"https://mcp.dida365.com","headers":{"Authorization":"Bearer <你的令牌>"}}}}}
```

**验证标准**：配置保存/连接后，确认工具列表出现滴答相关工具，且以下 5 类能力全部可用——
   - 列出项目（list projects）
   - 筛选/查询未完成任务（filter/undone tasks）
   - 查询已完成任务（completed tasks）
   - 按关键词搜索任务（search tasks）
   - 新建任务（batch add）与标记完成（complete task）

验证通过后回到对话，告诉 agent"滴答 MCP 已配好"。

## 铁律（每条都出过事故，违反即 bug）

1. **绝对日期，永不写"今天/明天"**：文件标题、章节标题只允许 `2026-10-05` 这种绝对日期；相对日期一觉醒来就是错的。
2. **总表倒叙**：`待办总表.md` 按日期倒序——最新的截止在最上面，旧的自然下沉；每天只在顶部插新区块。
3. **扫全部活跃会话，不许用固定群名单偷懒**：任务经常发在新拉的群里。每次运行必须先 `wxcli sessions` 列全量，凡断点之后有新消息的逐个看；新群/新联系人默认"可能有任务"。
4. **滴答单任务单日期**：一条滴答任务从标题到 due 到正文自述只允许一个日期；跨多日期的事项拆成多条各挂各日。正文写来源不带日期，历史进展不带日期；末尾【原始信息】原文照抄区天然带日期，不算违反。
5. **用户范围限定**：每个用户的适用范围不同（校区、年级、职务、身份）。第一次运行时向用户确认其范围限定词并写进 README（如"我是 X 校区学生""我只做 X 职务的活"）；通知原文限定别人做的事，一律不派给用户、记入作废区并注明原因；建任务时不许丢原文的范围限定词，存疑先看原文再建。
6. **滴答正文末尾必附【原始信息】**：每条滴答任务的 content 最后追加 `【原始信息】（来源群 · 发送人 · 时间）` + 通知原文逐字照抄（含随附文件名）；同一事项拆多条的每条都要附；个人自建任务附 `【原始信息】个人自建任务，无微信原文。`。
7. **凡有日期/时间的事项一律建滴答任务**：活动日、截止日、报名窗口、可选活动、收到免回复的小事——不管多小都要建并挂日期；没具体日期的建无截止占位任务注明"届时补日期"；范围型事项建一条挂起始日或截止日。
8. **滴答去重三查**：新建任何任务前，必须同时查**未完成列表 + 已完成列表 + 关键词搜索**——已提交的不重复建；已打勾的（status=completed）一律视为已完成，既不重建也不再提醒。历史完成也进总表"已完成"区。
9. **优先级排序**（可被用户在 README 覆盖）：默认 **用户本人组织/职务的事（学生会、班委、部门） > 老师/班主任/上级发的 > 其他按截止紧急度**；汇报与总表排序都按此。
10. **新文件必归档**：断点后收到的每个文件（docx/xlsx/pdf/zip/图片等）都要找到本地缓存、打开确认内容，按用户在 README 约定的文件夹分类归档；重复副本比对后处理；归档记录写进纪要和汇报。

## 工作流（按序执行，不可跳步）

### Step 0 · 定日期和断点
- `date +%F` 取今天真实日期，不许沿用文件里的日期。
- 读工作区 `README.md` 的"数据截至"时间戳 = 上次断点。
- 读 `待办总表.md` + `今日待办.md`，把所有 `- [ ]` 未完成项抄到临时清单——这是衔接校验的基准。

### Step 1 · 列全量会话，找断点之后动过的
```bash
export PYTHONIOENCODING=utf-8
~/.wechat-cli/wxcli.cmd sessions --limit 80
```
凡 `time` 晚于断点的会话全部进入扫描列表；对比 README"必盯清单"，没记录过的新群/新联系人优先扫并加进清单。公众号/资讯号跳过。

### Step 2 · 导出增量
```bash
~/.wechat-cli/wxcli.cmd history "<会话名>" --start-time "<断点日期 00:00 或上一断点>" --format text --limit 300
```
只看：班级/工作/通知群、老师上级、班委、私聊；**起点比断点早几小时**，防止会话列表分页漏掉边缘消息。要拿链接/文件详情时用 `--format json`。

### Step 3 · 关键词补盲
```bash
python <wechat-local>/scripts/search_all.py 截止 --context 3 --limit 40
```
换词多跑几轮：截止 / 交 / 报名 / 接龙 / 收到请回复 / @所有人 / 前；输出用 `grep "YYYY-MM-DD"` 过滤到断点后。**以 search_all.py 为准**（wxcli search 对压缩消息失明）。

### Step 4 · 判定与分类
每条新消息归入：**新待办（带截止）/ 已完成 / 作废（澄清误传、范围外）/ 纯通知 / 纯闲聊**。同一事项多次改期取最新；"发错了/不要看"标删除线进作废区；范围限定词先对照 README 里用户的范围再判定；**别人私聊交代的事优先级高于群通知**。

### Step 5 · 写 `日期纪要/YYYY-MM-DD.md`
每天一个文件，模板照抄前一天：当日要点、时间线表格、勾选清单、前瞻。

### Step 6 · 重写 `今日待办.md`
标题 `# 📌 今日待办 · <绝对日期>（周X）`。结构：⚡ 今天必须做（硬截止）→ 🟡 今天顺手处理 → 📅 接下来（按日期排序，只放未完成）→ ✅ 今天已完成 → ⚠️ 已作废。旧文件所有未完成项必须结转。

### Step 7 · 重写 `待办总表.md`（倒叙）
章节顺序（新的在上）：🔺 新增/更新 → 🔴 已过期/待确认 → 🟠 未来 7 天 → 🟡 远期截止 → 📖 长线 → 🔵 条件触发 → 📢 提醒类 → ✅ 已完成（倒序）→ ❌ 作废。每条写绝对截止日期。
**衔接校验（必做）**：Step 0 的旧未完成清单逐条对照新总表——每条要么还在、要么进已完成、要么进作废，三者之外不允许凭空消失，丢项立即补回。

### Step 8 · 滴答同步（去重后提交）
1. **查现状**：列未完成任务 + 查断点以来已完成任务 + 按事项关键词搜索——三项都查完才动手。
2. **勾已完成**：断点后用户在滴答里勾掉的、以及有明确证据闭环的占位任务（任务正文自带解除条件），一律视为完成，同步进总表已完成区；**不翻用户已勾的案**。
3. **建新任务**：排除已存在的，按铁律 4/6/7 组装（单日期 + 末尾原文照抄），按铁律 9 定优先级；有具体日期挂日期，无日期挂占位。
4. 逐条记录 taskId，汇报里列出"新建 N、勾掉 M、排除重复 K"。

### Step 9 · 文件归档
按铁律 10 找文件、开文件确认、分类移动/复制、记录。

### Step 10 · 更新 README 并汇报
- "数据截至"刷成本次时间；必盯清单加新群；"接下来最关键"改成当前视角。
- 按下面格式向用户汇报。

## 输出汇报格式

1. 本次断点→新断点的时间范围、扫了几个会话、新发现的群；
2. 新增待办（带绝对截止日期，按铁律 9 的优先级排序，每条写详细、有文件的点进去看了什么）；
3. 状态变化（完成/作废/改期/待确认）；
4. 滴答操作明细：新建 N 条（标题+日期）、勾掉 M 条、排除重复 K 条；
5. 文件归档明细（文件 → 去向文件夹）；
6. 衔接校验结果：旧 N 条未完成 → 现在都在哪；
7. 最近 3 天的硬截止 Top3。

## 工具坑速查

| 坑 | 解法 |
|---|---|
| `search_all.py` 报解密缓存缺失 | 先跑 `wxcli history 任意群 --limit 3`（只跑 sessions 不够） |
| `search_all.py` 报 `zstandard has no attribute ZstdDecompressor` | 临时目录坏包缺 `__init__.py`：把 `~/.wechat-cli/deps/zstandard/*` 复制到 `%LOCALAPPDATA%\Temp\wechat-cli-plus-pydeps\zstandard\` |
| `--context` 裸 flag 报错 | 必须带值：`--context 3` |
| bash 下中文输出乱码 | `export PYTHONIOENCODING=utf-8` |
| bash 里中文变量名赋值失败 | 用纯英文变量名或直接写完整路径 |
| wxcli search 搜不到通知 | 压缩消息盲区，用 search_all.py |
| 滴答 batch_add 报 unknown_exception | 检查 projectId 是否真实存在（先 list_projects 对照）、不要自定义任务 id |
| 文件被并发改动（Edit 报 modified） | 重 Read 再改；多会话共用工作区 |
